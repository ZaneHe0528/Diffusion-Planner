## 结论先说

能做,而且这正是你计划里 M3 阶段"小开发集扫操作点 × 分箱边界"的内容。更好的消息是:**挡位数和边界的消融不需要重训 gate**。我确认了 `gate_model.py` 里 gate 只有一个回归头(`head_reg` 输出连续 `d_hat`),`level` 只是推理时对 `d_hat` 按 `level_edges_m` 做 digitize;`num_levels` 只影响那个 buffer 的长度。所以消融只需改 `d_to_ops.py` 的边界和操作表(边界可以离线从已有标签分布重算任意分位数),推理端零训练成本。

## 消融设计建议

先把两个混杂因子拆开:①挡位数 K 与边界;②每档操作表 `(t_start 上限, steps)`。注意你 level 0–2 已经在用 continuous t_start(由 `d_hat/xy_std` 反解),所以挡位实际只决定 **steps 和 t_start 上限 + 最高档 full**——这决定了消融轴应该这样设:


| 消融轴            | 建议取值                                      | 说明                                                                                        |
| -------------- | ----------------------------------------- | ----------------------------------------------------------------------------------------- |
| 挡位数 K          | 2 / 3 / 4(现状)/ 6 / 无挡连续                   | "无挡连续"= continuous t_start + steps 也连续化(如 `ceil(t_start×10)`,下限 2)+ 单一 full 阈值,是很有说服力的对照行 |
| 边界方案           | 等频分位数(现状 [0.5, 0.75, 0.9])/ 等宽(米)/ 闭环代价驱动 | 等频 vs 等宽是标准消融;代价驱动只在小开发集扫                                                                 |
| **hard 阈值分位数** | 0.8 / 0.85 / 0.9(现状)/ 0.95                | **这是影响最大的单一参数**,直接控制 full denoise 比例,决定 NFE–分数权衡点,优先扫它                                    |
| 各档 steps       | (2,4,7,10) 现状 vs (3,5,7,10)               | 针对 Comfort 掉分,level 0 加 1 步只增加约 0.5 平均 NFE                                                |
