# 用 x0 重加噪实现帧间复用，而非 Falcon 原文的 latent buffer

Falcon 原文缓存去噪过程的全部中间状态（多帧 latent buffer + 温度 softmax 选起点 + 探索率 δ）。本项目偏离原文：只缓存上一帧的最终干净轨迹（物理空间），当前帧做 SE(2) 对齐 + 时移后，用 VPSDE 前向公式重新加噪到固定中间水平 t_s，从 t_s 起跑 DPM-Solver（SDEdit 风格）。

理由：(1) 中间噪声状态存在于归一化空间，反归一化→SE(2) 旋转→再归一化的链条会破坏噪声分量的统计特性，而干净轨迹对坐标变换封闭；(2) nuPlan 每 0.1s replan、相邻帧轨迹重叠 79/80，上一帧几乎总是最优候选，多帧 buffer 与 softmax 采样是无效复杂度；(3) DPM-Solver 10 步只产生约 11 个离散中间状态，可选噪声水平太粗，重加噪的 t_s 可连续取值；(4) 驾驶场景中随机探索（δ）有安全风险，由确定性的阈值回退取代。

被否决的备选：忠实移植 latent buffer（含作为消融实现一份）——评估后认为在高频 replan 场景下无增益预期，不值得实现成本。
