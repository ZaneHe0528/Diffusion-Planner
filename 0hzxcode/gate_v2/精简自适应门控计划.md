# 精简自适应门控(轻量 gate)设计方案

## 1. 一句话逻辑
场景信息(自车运动学为主) → 场景复杂度 → 帧间变化距离 d_hat → warm-start 操作点(再加噪时刻 t_s + 去噪步数)。d 小=简单=多复用少去噪(加速);d 大=复杂=少复用甚至完整去噪。

## 2. 需要哪些指标(砍到最小)

保留两组输入,其余(`lanes` / `route_lanes` / `static_objects` / `prev_d`)全部删除。依据:`ego_only` 与 `all_groups` 的 Spearman 几乎相同(0.643 vs 0.641),静态障碍贡献≈0,`prev_d` 有闭环分布漂移风险。

- **ego 运动学(主信号)** — 复用 [gate_model.py](0hzxcode/gate/gate_model.py) 里已有的 `derive_ego_kinematics`(14 维)+ 原始 `ego_history [21,7]`。这 14 维本身就是"复杂度"的显式刻画,与场景排行一一对应:
  - 静止/跟停(低 d): `cur_speed≈0`、`accel≈0`、`yaw_rate≈0`、`is_stopped=1`
  - 起步/急加速(高 d): `accel` 大、`speed_delta` 大
  - 转弯/变道(高 d): `|yaw_rate|`、`curvature`、`steering`、2s 累计 `net_heading` 大
- **邻车轻量组(只补 hard 帧)** — `neighbor_agents [32,21,11]`,用现有 `TokenBranch`。只为多抓交互类突变帧(上下客/避让/near_multiple_vehicles),AUROC +~0.015;对秩相关几乎无增益,可作为可关消融项。

关键:复杂度不需要单独造一个指标,它就是 d_hat 的单调函数——gate 直接学 ego 运动学 → d_hat 即等价于"复杂度打分"。

## 3. 门控网络结构(比现有更薄)

在现有 `RawObsGate` 基础上裁剪:
- 分支只留两条: ego 分支 `MLP(21*7+14 → 128 → 64)`;邻车分支 `TokenBranch(→64)`。
- trunk: `concat(128) → LayerNorm → Linear(128)+SiLU`(单隐层,对齐 BLUE)。
- **只留回归头** `d_hat`(标准化 log1p(d) + Huber);删掉分类头,`level` 直接对 `d_hat` 做 `bucketize(level_edges_m)` 得到(边界仍存 checkpoint)。少一个头=更简单,且档位与连续值口径一致。
- 参数量: ego 分支~27K + 邻车分支~45K + trunk~16K ≈ **<0.1M**,比现在 0.23M 还小。
- 训练/评测管线不变: `train_gate.py --enable-groups ego_history neighbor_agents`,直接产出 ego(+nbr) 版 run。

## 4. d_hat → 复用程度 / 再加噪程度(方案核心)

现状: [decoder.py](diffusion_planner/model/module/decoder.py) 推理时 `xT = [current_state, randn*0.5]` 从纯噪声起步,`dpm_sampler(diffusion_steps=10)` 从 t=T 去噪到 0。底层 [sampling.py](diffusion_planner/model/diffusion_utils/sampling.py) 的 `DPM_Solver.sample` 已支持 `t_start` 与 `steps` 参数,warm-start 无需改采样器。

warm-start(Falcon 式)改为: 取上一帧去噪结果 `x0_prev`(自车系对齐到当前帧) → 只加噪到中间时刻 `t_s < T`(再加噪) → 从 `t_s` 去噪到 0,步数减少。

- **t_s 由 d_hat 反解噪声调度(物理量纲对齐)**: VP 调度下 `x_{t_s}=alpha(t_s)*x0_prev + sigma(t_s)*noise`;令 `sigma(t_s) ≈ 归一化后的 d_hat`(用 `state_normalizer` 把米折算到状态空间),反解出 `t_s`。d 越小 → 需要注入的噪声越少 → `t_s` 越小 → 复用程度越高。
- **步数随 t_s 缩放**: `steps = clamp(ceil(base_steps * t_s / T), min_steps, base_steps)`。t_s 小则 2-3 步即可。
- **落地用分档(工程更稳)**,边界取全量 normalized-L2 分位(见 [分析结果.md](0hzxcode/adjacent_traj_l2_output/分析结果.md): P50=0.275/P75=0.696/P90=1.385):
  - 低档 d≤~0.28: 激进复用,`t_s` 最小,`steps≈2`
  - 中档 0.28<d≤0.70: `t_s` 中,`steps≈3-4`
  - 高档 0.70<d≤1.39: `t_s` 大,`steps≈6-8`
  - 满档 d>1.39: 不复用,`t_s=T`,`steps=10`(退回完整去噪)

## 5. 安全兜底(必要,来自现有分析)
- **保 recall 的阈值校准**: 用 val 集把 d_hat 阈值标到 hard recall≥95%(现管线已有),漏判 hard 帧的代价远大于少省几步。
- **邻车组触发保守化**: 邻车分支判定强交互时,即使 ego 平稳也上调一档,避免上下客/避让类突变被放过。
- **误差累积**: partial-denoise 复用会累积误差(分析已提示,`following_lane_with_lead` 的 d 波动可能主要来自采样噪声)。建议先在低风险类(stationary/stopping/behind_long_vehicle)开复用验证,再逐步放开。

## 6. 闭环接入点(本次仅记录,不实现)
- 在 planner 缓存上一帧 `x0`,并做自车系 ego-shift 对齐;
- gate 前向得 `d_hat` → 映射表得 `(t_s, steps)`;
- `decoder.py` 里把 `xT` 改为 `re_noise(x0_prev, t_s)`,调用 `dpm_solver.sample(x, steps=steps, t_start=t_s)`,index-0 的 `current_states` 约束保留。

## 7. 相对现有设计的删减清单
- 删: `lanes` / `route_lanes` / `static_objects` / `prev_d` 四组输入;删分类头。
- 留: ego 运动学 + 邻车轻量组、回归头、level 边界 buffer、标准化 buffer、group-dropout(便于消融)。
- 新增(仅设计,后续实现): d_hat→(t_s, steps) 映射 + warm-start 再加噪接入。
