## nuPlan 数据集有多大？

nuPlan 不是单一文件，而是 **Log 数据库（.db）+ HD Map +（可选）传感器数据** 的组合。

### 官方规模（nuPlan v1.1）


| 分包                      | 磁盘大小        | 驾驶时长       | Log 数量    | 城市                | 用途      |
| ----------------------- | ----------- | ---------- | --------- | ----------------- | ------- |
| **mini**                | **~13 GB**  | 7 h        | 64        | 拉斯维加斯、波士顿、匹兹堡、新加坡 | 快速调试    |
| **完整 v1.1（trainval 等）** | **~1.8 TB** | **1282 h** | **15910** | 同上 4 城            | 正式训练与评测 |


论文与官方 benchmark 也对应这一规模：**1282 小时**真实驾驶、**73 种**场景类型、4 个城市。

### 各 split 大致体量（第三方统计，供参考）


| Split | 约计大小             |
| ----- | ---------------- |
| Train | ~947 GB          |
| Val   | ~90 GB           |
| Test  | ~89 GB           |
| Mini  | ~8 GB（log DB 部分） |


完整 train+val+test 的 log 合计约 **1.1 TB+**，与官方 **1.8 TB** 同一量级（含压缩/元数据差异）。

### 地图（Maps）

- 包名通常：`nuplan-maps-v1.0.zip`
- 体量相对很小，一般 **几百 MB 量级**
- **Diffusion Planner 训练和闭环仿真都必须有**

### 传感器数据（Sensor Blobs）——一般不需要


| 类型                | 规模                                        |
| ----------------- | ----------------------------------------- |
| 完整传感器（相机 + LiDAR） | 官方称全量 **200+ TB**                         |
| 已公开发布的 sensor 子集  | 目前主要是 **mini 对应** 的 blobs，约 **150 GB** 量级 |


Diffusion Planner 用的是 **向量化地图 + 轨迹/目标标注**，**不读相机/LiDAR**。本仓库 `data_process.py` 里 `sensor_root = None`，说明预处理阶段也 **不需要 sensor**。

## 你需要下载哪些？

取决于你的目标：

### 方案 A：只做闭环评测（用官方 checkpoint）

这是 **最省空间** 的路径。


| 必下                    | 说明                                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| **nuplan-devkit**     | 代码环境，不是数据                                                                                          |
| **Maps**              | `nuplan-maps-v1.0`                                                                                 |
| **Log 数据库（trainval）** | Val14 / Test14 / Test14-hard 场景来自 trainval 中的 `.db`                                                |
| **模型权重**              | [HuggingFace](https://huggingface.co/ZhengYinan2001/Diffusion-Planner) 的 `args.json` + `model.pth` |



| 不需要          | 说明                                                                       |
| ------------ | ------------------------------------------------------------------------ |
| Sensor blobs | 规划任务用不到                                                                  |
| 完整 1.8 TB    | 若只做 val14 评测，理论上只需包含评测 log 的子集；但官方 split 常跨多个 log，**最稳妥仍是下载完整 trainval** |


**预估磁盘：Maps + 完整 trainval ≈ 1.8 TB+**（若只下 mini，**无法**跑官方 Val14/Test14 benchmark）。

---

### 方案 B：从零训练 Diffusion Planner（复现论文）


| 必下                           | 说明                          |
| ---------------------------- | --------------------------- |
| **Maps**                     | 同上                          |
| **完整 trainval log（~1.8 TB）** | 论文从训练集采样 **100 万 scenario** |
| **nuplan-devkit**            | 数据加载与仿真                     |
| **（可选）HuggingFace 权重**       | 若只做 finetune 可跳过            |



| 不需要           | 说明     |
| ------------- | ------ |
| **Sensor 数据** | 本仓库不使用 |


**额外磁盘（预处理产物）：**

运行 `data_process.sh` 后会生成约 **100 万个 `.npz`** 和 `diffusion_planner_training.json`。这部分通常还要 **数百 GB 到 1 TB+**，取决于存储格式，需单独预留。

本仓库预处理配置：

```4:14:data_process.sh
NUPLAN_DATA_PATH="REPLACE_WITH_NUPLAN_DATA_PATH" # nuplan training data path (e.g., "/data/nuplan-v1.1/trainval")
NUPLAN_MAPS_PATH="REPLACE_WITH_NUPLAN_MAP_PATH" # nuplan map path (e.g., "/data/nuplan-v1.1/maps")
...
--total_scenarios 1000000 \
```

`nuplan_train.json` 里约 **13181 条** log 名，用于筛选训练 log。

---

### 方案 C：快速跑通流程（调试代码）


| 必下                   | 说明                 |
| -------------------- | ------------------ |
| **mini log（~13 GB）** | `nuplan-v1.1_mini` |
| **Maps**             | 必须                 |



| 局限                     | 说明                       |
| ---------------------- | ------------------------ |
| 不能复现论文 Val14/Test14 分数 | 官方 benchmark 不在 mini 上   |
| 不能完整训练                 | 数据量远小于论文的 100 万 scenario |

## 建议

1. **先明确目标**：只评测 → 下 trainval + maps；只调试 → mini + maps 即可。
2. **Sensor 可以不下载**：Diffusion Planner 全流程不需要。
3. **训练还要预留预处理空间**：100 万 npz 往往和原始 log 同量级甚至更大。
4. **磁盘紧张时**：先用 mini 验证 devkit / 预处理 / 仿真链路，再补全 trainval。
